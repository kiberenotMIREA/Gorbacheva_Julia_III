## 1. Паспорт проекта

- **Название проекта:** Обнаружение уязвимостей C/C++ кода с использованием ансамбля моделей (BERT + LSTM)
- **Автор:** Горбачева Юлия Павловна
- **Группа:** КТСО-12-24
- **Контакт:** @yuliyaenot

Проект посвящен разработке сервиса автоматического обнаружения уязвимостей в исходном коде C/C++ с использованием ансамбля моделей (BERT + LSTM). Используется датасет VulDeePecker. Реализованы модели (LogisticRegression, BiLSTM, DistilBERT с mean pooling) и ансамбль Stacking (BERT + LSTM, 801-d мета-признаки, F1=0.805). Финальный результат — REST API на FastAPI, который по фрагменту кода возвращает вероятность наличия уязвимости.

## 2. Постановка задачи и контекст

### Предметная область и задача

Современные практики DevSecOps предполагают автоматизированный анализ исходного кода на этапе CI/CD. Статические анализаторы (SAST) дают много ложных срабатываний, что делает актуальным применение глубокого обучения.

**Задача:** Бинарная классификация фрагментов C/C++ кода — уязвим (1) или безопасен (0).

**Пользователь:** Security-аналитик / разработчик, проверяющий код на этапе code review.

### Формулировка задачи в терминах ML

- **Входные данные:** Исходный код функций на C/C++ (строки)
- **Целевая переменная:** Бинарная метка (0 — безопасный, 1 — уязвимый)
- **Ограничения:** CPU-only, ~3000 примеров, ограниченные вычислительные ресурсы

### Целевые метрики

- **Recall (полнота)** — минимизация пропущенных уязвимостей (False Negative) критична для безопасности
- **F1-score** — баланс точности и полноты
- **ROC-AUC** — общая способность модели разделять классы
- **Accuracy** — общая точность (вспомогательная метрика)

## 4. Модели и подходы

### Базовые (baseline) модели

**Model 1: TF-IDF + LogisticRegression**
- Векторизация: char-level TF-IDF (n-grams 3-6, max_features=10000)
- Простая интерпретируемая модель

### Нейросетевые модели

**Model 2: Bidirectional LSTM**
- Архитектура: Embedding(64) → BiLSTM(64) → Dropout(0.3) → BiLSTM(32) → Dropout(0.3) → Dense(32, 'penultimate') → Dense(1, sigmoid)
- Символьная токенизация, maxlen=200
- Class weights для борьбы с дисбалансом
- 5 эпох, batch_size=32

**Model 3: DistilBERT + LogisticRegression (mean pooling)**
- Feature extraction: mean pooling эмбеддинг (768-d) + L2-нормализация
- DistilBERT-base-uncased в режиме eval
- Mean pooling дает более робастное представление для кода, чем [CLS]

### Experiment tracking (ноутбук: `notebooks/00_full_pipeline.ipynb`, разделы 4-7)

Проведенные эксперименты:
1. BiLSTM без class weights → низкий Recall (0.286)
2. BiLSTM с class weights → Recall улучшен до 0.857
3. DistilBERT feature extraction ([CLS]) → F1=0.667
4. DistilBERT + class_weight='balanced' + **mean pooling** → F1 улучшен
5. **Ensemble Stacking (BERT + LSTM, 801-d мета-признаки) → F1=0.805, Recall=0.750, Precision=0.868**
6. BERT mean embedding (768-d) напрямую в мета-признаки (не только через LR)
7. BERT-LR proba (1-d) + BERT mean embed (768-d) + LSTM penultimate (32-d) → 801-d мета-признаки

## 6. Архитектура решения и сервис

### Архитектура пайплайна

```
VulDeePecker (HuggingFace) → Preprocessing (dedup, filter) → 
  ├── TF-IDF → LogisticRegression
  ├── Char Tokenizer → BiLSTM → 32-d penultimate features
  ├── DistilBERT → 768-d mean pooling embeddings (L2-norm) → LogisticRegression
  └── Stacking (801-d meta): 
        BERT-LR proba (1-d) + BERT mean embed (768-d) + LSTM penultimate (32-d) 
       → Meta-classifier (LR/GB/SGD) → FastAPI → /predict
```

### API и endpoints

| Endpoint | Метод | Описание |
|----------|-------|----------|
| `/health` | GET | Проверка состояния сервиса, загрузки модели |
| `/methods` | GET | Список доступных методов обнаружения дефектов |
| `/predict` | POST | Принимает code + method, возвращает предсказание |

**Вход `/predict`:**
```json
{
  "code": "void func() { char buf[10]; strcpy(buf, input); }",
  "method": "ensemble"
}
```

**Выход:**
```json
{
  "prediction": 1,
  "label": "vulnerable",
  "probabilities": [0.214, 0.786],
  "confidence": 0.786,
  "inference_time_ms": 2450.32,
  "method": "ensemble"
}
```

### Технологический стек

- **Язык:** Python 3.11

- **API:** FastAPI + Uvicorn
- **Контейнеризация:** Docker, docker-compose
- **Тестирование:** pytest, httpx
- **Конфигурация:** YAML, .env (python-dotenv)

## 8. Ограничения и дальнейшая работа

### Текущие ограничения

- Модель обучена на подвыборке (~5000 из 160,000) из-за CPU-only
- DistilBERT в режиме feature extraction (fine-tuning опционален, ~15 мин на CPU)
- LSTM обучен с EarlyStopping (обычно 5-8 эпох)
- BERT-эмбеддинги могут вызвать OOM на сервере с 3.8 GB RAM
- Не реализована авторизация/аутентификация
- Нет персистентного хранения истории запросов
- Нет Grafana для визуализации Prometheus метрик

### Направления развития

1. **Улучшение модели:** Optuna для гиперпараметров, увеличение эпох LSTM, fine-tuning DistilBERT
2. **Расширение задачи:** мультиклассовая классификация по CWE (CWE-119, CWE-399, другие)
3. **Оптимизация:** квантование DistilBERT, ONNX Runtime для ускорения инференса
4. **Инфраструктура:** Grafana для визуализации Prometheus метрик, авторизация, CI/CD (GitHub Actions)
5. **Данные:** обучение на полном датасете, аугментация кода
6. **Ансамбль:** больше базовых моделей (LightGBM, CatBoost), Optuna для мета-классификатора
